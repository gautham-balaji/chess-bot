# Archived invalid benchmark artifacts (Phase 1)

These files are preserved **as evidence**, not as working code. They are the
originals as they existed at Phase 0 baseline commit `ccd24c4`, before Phase 1
disabled or removed them.

Phase 0 verified that every quantitative output of these files was fabricated,
hardcoded, or synthetic. None of it was a measurement.

| File | Why it is here |
|---|---|
| `benchmark_stockfish.py.original` | Was **untracked** in git, so deleting or editing it in place would have destroyed it permanently. Line 57 set the top-move agreement rate with `np.random.rand() < 0.7`, discarding the real moves computed on the two preceding lines. Lines 113-126 printed hardcoded timing statistics while ignoring the measured lists built at lines 109-110. |
| `generate_visualizations.py.original` | Was **untracked**. Every plotted value was a hardcoded literal; the "training curves" were generated by `25000*np.exp(-epochs/15)+15000+np.random.normal(...)` rather than from real training history. |
| `accuracy_metrics.png` | Output of the above. Plotted a hardcoded 0.55 "top move agreement" and a 180cp "MAE" that is computed nowhere in the project. |
| `architecture_breakdown.png` | Output of the above. Hardcoded layer parameter counts. |
| `performance_comparison.png` | Output of the above. Asserted this engine is "6.2x faster" and "62x faster" than Stockfish. Phase 0 measured it ~121x **slower**. |
| `training_progress.png` | Output of the above. Fully synthetic curves, while genuine per-epoch history exists in `chess_model_FINAL.ipynb` cell 15. |

The four PNGs were also tracked in git at `ccd24c4` and remain recoverable from
history; the copies here exist so the evidence sits alongside the explanation.

Verified figures are in `baseline/BASELINE.md`.
